# apps/mobile — chess-mobile

Loaded when working under `apps/mobile`. Cross-app rules live in the root `CLAUDE.md`; the plan is OpenSpec
`mobile-app` (design D1–D13, tasks by group).

## Commands

```bash
pnpm exec nx run-many -t lint test build -p mobile   # typecheck, expo lint, prettier, pins, expo-doctor; jest; export
pnpm exec nx run mobile:start                        # dev server over an Expo tunnel, for the development build
pnpm exec nx run mobile:apk                          # build/development.apk: prebuild + Gradle, outside the sandbox
pnpm exec nx run mobile:apk-release                  # build/release.apk, arm64-v8a, needs CHESS_ANDROID_KEYSTORE* (README)
pnpm exec nx run mobile:ipa                          # build/Chess-<version>.ipa, unsigned, on a Mac only
tools/mobile/publish.sh <version> [--dry-run]        # the APK (and an .ipa) to the GitHub Release mobile@<version>
pnpm exec nx run mobile:test-native                  # the Stockfish bridge on the host (g++, real sf_19)
pnpm --dir apps/mobile doctor:android                # JDK 17, SDK 36, build-tools, NDK 27, CMake 3.22.1
```

Inside the agent sandbox run Expo commands with `EXPO_NO_TELEMETRY=1` (telemetry writes `~/.expo`) and
`NODE_USE_ENV_PROXY=1` (expo-doctor fetches from `exp.host` / `reactnative.directory`).

## Set-up notes

- Expo SDK 57, pinned exactly (`check:pins`); add packages with `pnpm expo install <pkg>`, then pin what it wrote. The
  patches are the ones expo-doctor expects; the repo's `minimumReleaseAge` (7 days) applies.
- Metro needs no workspace configuration: Expo's default follows pnpm's symlinks into `libs/*` (TS source with `.ts`
  imports) and gives the bundle one React (19.2.3). **Jest does not**: `jest.config.js` maps `react` to this app's
  copy, or a `@chess/view` hook fails with "Invalid hook call" (the libraries keep React 19.2.7 for the web apps).
- `expo:doctor` is `scripts/expo-doctor.js`: expo-doctor with one finding tolerated, the libraries' own test React
  (`libs/*/node_modules/react`); anything else fails.
- `test-renderer` is overridden to 1.2.0 in `pnpm-workspace.yaml` (1.3.0 needs React 19.3).
- `src/app` holds routes only (Expo Router bundles every file there); route tests go in `src/__tests__/app/`.
- `build` exports Android and iOS (not web); iOS bundles without a Mac, only native builds need one.
- Android builds 64-bit only (`buildArchs` in `app.config.ts`: `arm64-v8a` phones, `x86_64` the emulator): Stockfish 19
  uses `__int128`, which `armeabi-v7a`/`x86` lack. `build-android.sh` logs the whole build to `build/<profile>.log`.
- `android/` and `ios/` are generated by `expo prebuild` and never committed; everything native is in `app.config.ts`'s
  plugins. `expo prebuild` runs in the sandbox (it checks the plugins); Gradle does not (the owner runs `mobile:apk`).
- The toolchain scripts (`setup-android.sh`, `doctor-android.js`) come from SpanishGameApp; this machine has them set up.
- Stockfish (D6): `tools/mobile/fetch-stockfish-src.mjs` → `modules/stockfish/vendor/` (git-ignored, 96 MB with the
  network). `modules/stockfish/cpp/bridge.cpp` runs Stockfish's UCI loop on its own thread with `cin`/`cout` swapped;
  Stockfish's files are never edited. `# request {json}` and `# crash-test` (only with `SFBRIDGE_CRASH_TEST`) are
  the bridge's own lines and never reach Stockfish.
- The Android side of the module: `modules/stockfish/android` (Kotlin `StockfishModule`, JNI glue, `CMakeLists.txt`
  compiling Stockfish + the bridge at `-O3` in every build; `-Wa,-I<src>` so INCBIN finds the network). The
  crash test is compiled into Debug only. Cross-compiling with the NDK's clang works in the sandbox (Gradle does not).
- `/dev/engine` (development builds only, linked from home) is the engine check: what the last run left, a move with
  its time, and the crash test.
- The iOS side: `modules/stockfish/ChessStockfish.podspec` (at the module root: CocoaPods takes no source outside its
  folder; `expo-module.config.json` points at it), `ios/SFBridge.{h,mm}` (Objective-C++ over the C++ bridge, the only
  public header) and `ios/StockfishModule.swift`. Not buildable here; a Mac runs `pnpm fetch-stockfish` before
  `pod install`. Unverified until the friend's first build (task 3.5).

## Screens and tests

- Routes only in `src/app` (thin files); each screen is in `src/screens/<feature>.tsx`, its pieces in
  `src/components/`. Tabs are `src/app/(tabs)/<tab>/` with a stack each; a game in play is `src/app/play/games/[id]`
  over the tabs (D5). Desktop paths map to the phone's through `mobileRoute` (`MobileLink`); external links go through
  `ExternalLink` (the browser, never the app).
- The board (`components/board.tsx`) owns picking, drags, promotion, premoves (`onPremove`) and arrows, and hands up
  UCI; `TreeBoard` is the analysis board and a study's. One responder over the board (`pointerEvents="box-only"`): put
  anything pressable over it beside that layer, not in it.
- Theme: `ThemeProvider` from `PreferencesProvider` (the database's preferences); colours are hex tokens checked
  against `theme.css` by `tokens.test.ts`.
- Route tests (`src/__tests__/app/*.test.tsx`) render the real `src/app` with `renderRouter`, on services over Node's
  SQLite: `jest.mock('@/lib/app', …)` → `testing/app.ts#startTestServices`. Start the app with `startApp()` (scripted
  engine answers, platform overrides) and write data before rendering; `reopen()` renders on the same database;
  `tapSquare()` taps the board. expo-router's testing library turns fake timers on: never wait on a raw `setTimeout`,
  and never put a database read in `waitFor` (overlapping `act()` breaks the rest of the file) — wait on the screen,
  then read the database once.
